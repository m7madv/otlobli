# ضمانك للأعمال 4.4.0

تطبيق `Flutter` عربي مخصص لإصدار الضمانات الرقمية ومتابعة الصيانة للمتاجر في الخليج، مع أدوات اختيارية للفروع والمخزون ونقطة البيع. يبدأ من رحلة الضمان القصيرة، ويعمل على `Android` و`iOS` والويب، ويمكن فتح عرض تشغيلي كامل بلا خادم أو تكلفة.

## ما يغطيه النظام

### الحساب ومساحة المتجر

- تسجيل وإنشاء حساب عبر `Google` أو `Apple` فقط، من دون بريد وكلمة مرور خاصين بضمانك.
- إنشاء متجر أو الانضمام برابط دعوة أو `QR` مع رمز احتياطي، وحساب مستقل لكل موظف بصلاحيات مالك ومدير وموظف.
- جلسة محفوظة، حذف حساب آمن، ونقل ملكية المتجر إلى عضو آخر قبل حذف المالك عند الإمكان.
- تجربة وخطط وحدود شهرية مفروضة داخل قاعدة البيانات، ثم اشتراك أصلي موثّق خادمياً عبر `App Store` و`Google Play` من دون تفعيل يدوي.

### الاشتراك والفوترة

- أسعار وعملات محلية تصل مباشرة من متجر الجهاز، مع دورات شهرية وسنوية لخطط بداية ونمو وتوسع.
- شراء واستعادة وترقية وخفض وإدارة التجديد من المتجر، وعدم منح الاستحقاق للدفعات المعلّقة.
- تحقق خادمي مباشر من `App Store Server API` و`Google Play Developer API` قبل تفعيل الخطة أو إكمال معاملة المتجر.
- ربط الإيصال بحساب المالك والمتجر، وتخزين رمز `Google Play` في نطاق خادمي خاص لإعادة فحص التجديد والإلغاء.
- مدفوعات نقطة البيع الخاصة بعملاء المحل منفصلة تماماً عن اشتراك ضمانك.

### رحلة الضمان الأساسية

- يبدأ التطبيق بمسح باركود المنتج أو إدخاله يدوياً، ثم بيانات العميل والمدة.
- يدعم مسح الرقم التسلسلي أو كتابته، وإصدار بطاقة ضمان ومشاركتها برابط تحقق موقّع ورمز `QR`.
- يستطيع العميل فتح البطاقة العربية بلا تنزيل التطبيق أو إنشاء حساب، مع إخفاء بياناته الحساسة.
- ترتبط طلبات الصيانة بالضمان نفسه وتبقى حالتها واضحة للفريق.

### أدوات المتجر الاختيارية

- نوع الموقع: متجر بيع، مستودع، مركز صيانة، أو موقع هجين.
- مدير وتواصل وعنوان ومنطقة زمنية وساعات عمل وبادئة إيصال لكل فرع.
- تحديد قدرة الموقع على البيع أو استقبال الخدمة، وفرع رئيسي افتراضي.
- جلسات صندوق برصيد افتتاحي، مبيعات ومرتجعات نقدية، جرد ختامي، وعجز أو زيادة.

### البيع والإيصالات

- يبدأ التطبيق مباشرة من نقطة البيع، مع بحث ومسح باركود خاص بالتطبيق وإضافة المنتج بلمسة واحدة.
- سلة وكميات وأسعار وإيصال بيع داخلي بلا حقول ضريبية في مسار الموظف.
- لا تظهر بيانات العميل إلا عند ربط البيع به أو عند وجود ضمان، وتبقى الأرقام التسلسلية إلزامية للأجهزة المتسلسلة فقط.
- تقسيم الدفع والخصم والملاحظة خيارات مطوية، والإيصال مرقم من الفرع.
- خصم المخزون وإنشاء الضمانات المؤهلة وتحديث الصندوق ضمن العملية نفسها.
- مرتجع جزئي أو كامل يعيد المخزون، يسجل رد المبلغ، ويلغي الضمان المرتبط عند الإرجاع الكامل.

### المخزون والمشتريات

- رصيد منفصل لكل منتج وفرع، وكمية محجوزة وحد إعادة طلب ومتوسط تكلفة.
- تسوية جرد موثقة وتحويل ذرّي بين الفروع وسجل حركة كامل.
- تكلفة شراء وسعر بيع وتتبع مخزون وخيار أرقام تسلسلية في بطاقة المنتج.
- دليل موردين وأوامر شراء متعددة الأصناف واستلام يحدّث الكمية ومتوسط التكلفة.

### الخدمة والتقارير

- ضمان وإيصال موحدان، ومشاركة برابط تحقق لا يعرض رقم هاتف العميل كاملاً.
- طلبات صيانة مرتبطة بالضمان وحالات تشغيلية واضحة.
- عملات `SAR/AED/KWD/QAR/BHD/OMR/USD/SYP` بدقة صحيحة لكل عملة.
- تقارير المبيعات وطرق الدفع وتصدير `CSV` وسجل تدقيق.

## الحد القانوني للإيصال

الإيصال الصادر من هذه النسخة سجل بيع داخلي لإدارة المخزون والضمان، وليس فاتورة ضريبية إلكترونية معتمدة. المتجر الذي تلزمه دولته بفاتورة ضريبية رسمية يحتاج إلى وحدة امتثال محلية أو تكامل مع مزود معتمد قبل استخدام «ضمانك» بديلاً عن نظام الفوترة الرسمي. تحتفظ قاعدة البيانات بالأعمدة التاريخية للتوافق، لكن العمليات الجديدة تسجل الضريبة بقيمة صفر ولا تعرض إعداداتها للموظف.

## قاعدة البيانات والحماية

- طبقة `DamanakRepository` تفصل الواجهة عن العرض المحلي و`Supabase`.
- سياسات `RLS` تعزل بيانات كل متجر، وتتحقق العمليات من العضوية والدور على الخادم.
- البيع والتحويل والجرد والمرتجع وأمر الشراء وجلسة الصندوق دوال ذرّية `SECURITY DEFINER`، وليست تحديثات واجهة متفرقة.
- لا يوجد مفتاح خدمة سري داخل تطبيق الجوال، وملفات المفاتيح الفعلية مستثناة من `Git`.
- لا تطبّق مخطط ضمانك على قاعدة تطبيق آخر.

طبّق جميع ملفات `supabase/migrations` بترتيب الاسم، ثم انشر دوال مجلد `supabase/functions` المطلوبة للبيئة. توجد أسماء منتجات المتجر وأسرار الفوترة واختبارات القبول في [`docs/STORE_BILLING_SETUP.md`](docs/STORE_BILLING_SETUP.md)، وسياسة الذكاء الاصطناعي والحصص وتهيئة `API` و`webhooks` في [`docs/AI_AND_INTEGRATIONS.md`](docs/AI_AND_INTEGRATIONS.md).
إعداد مزودي الدخول ودعوة الموظف موثق في [`docs/AUTH_AND_TEAM_SETUP.md`](docs/AUTH_AND_TEAM_SETUP.md).

## التشغيل المحلي

بلا مفاتيح يفتح التطبيق عرضاً تشغيلياً واضحاً ولا يرسل بيانات إلى خادم:

```bash
flutter pub get
flutter run
```

للمزامنة السحابية، أنشئ مشروع `Supabase` مستقلاً، ثم:

```bash
supabase link --project-ref YOUR_DAMANAK_PROJECT_REF --workdir damanak_flutter
supabase db push --workdir damanak_flutter
flutter run --dart-define-from-file=dart-defines.json
```

## البناء والتوقيع

```bash
flutter analyze
flutter test
flutter build web --release
powershell -ExecutionPolicy Bypass -File scripts/build_signed_android.ps1
```

مفتاح رفع `Android` موجود خارج المستودع في مجلد المستخدم، وكلمة مروره محفوظة بتشفير حساب `Windows`. يبني السكربت `AAB` و`APK` موقّعين من دون طباعة السر.

لـ`iOS`:

- `.github/workflows/damanak-ios-unsigned.yml` يبني حزمة تحقق غير موقعة.
- `.github/workflows/damanak-ios-signed.yml` يبني `IPA` موقعة بعد إضافة أسرار شهادة وملف تزويد خاصين بالمعرّف `com.damanak.damanak`.

## الحالة الخارجية الحالية

- مشروع `Supabase` الإنتاجي المستقل هو `exxayzlklvgeyqhvtzgi`، والمخطط ودالة التحقق وترحيل الإيصالات المبسطة منشورة.
- شاشة الدخول تعرض `Google/Apple` فقط، ومسار دعوة الموظف يدعم الرابط و`QR` والرمز الاحتياطي؛ مزودا الدخول مفعّلان.
- منتجات اشتراك `App Store` الستة جاهزة للإرسال مع الإصدار، ومنتجات `Google Play` موجودة؛ قبول الشراء والاستعادة على حسابات الاختبار يبقى اختبار جهاز منفصلاً.
- الإصدار المنشور للاختبار الداخلي على المتجرين هو Build `20`. المصدر الحالي `4.4.0+21` تطويري محلي، ولم تُنشر بعد ترحيلات المطالبات والذكاء الاصطناعي والإشعارات والتكاملات أو Build `21`.
- قبول الكاميرا والخلفية والاستئناف وقارئ الشاشة على أجهزة حقيقية ما زال مطلوباً قبل النشر العام.
