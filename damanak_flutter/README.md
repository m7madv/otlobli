# ضمانك للأعمال 3.0.0

تطبيق `Flutter` عربي لإدارة بيع المنتجات وضماناتها وفواتيرها وخدمة ما بعد البيع للمتاجر في الخليج وسوريا. يعمل على Android وiOS والويب، ويمكن تجربته محلياً بلا أي خدمة مدفوعة.

## ما يغطيه النظام

### الحساب ومساحة المتجر

- تسجيل بالبريد وكلمة المرور، استعادة كلمة المرور، وجلسة محفوظة على الجهاز.
- إنشاء متجر جديد أو الانضمام إلى متجر قائم برمز دعوة مؤقت.
- حساب مستقل لكل موظف وصلاحيات `owner` و`manager` و`staff`.
- تجربة 14 يوماً وخطط اشتراك وحدود شهرية للأعضاء والضمانات تُفرض داخل قاعدة البيانات.
- تفعيل يدوي برمز أو طلب اشتراك؛ لذلك يمكن تشغيل المشروع بلا بوابة دفع أو تكلفة شهرية إلزامية.

### البيع والفاتورة والضمان

- ماسح باركود خاص بضمانك يستخدم كاميرا التطبيق، مع إضاءة وتبديل كاميرا وإدخال يدوي.
- مطابقة المنتج من كتالوج المتجر وتعبئة السعر ومدة الضمان تلقائياً.
- اختيار عميل وفرع وطريقة دفع ورقم فاتورة، أو توليد رقم الفاتورة تلقائياً.
- سعر بيع وخصم وضريبة وإجمالي، مع دعم الأسعار الشاملة أو غير الشاملة للضريبة.
- إصدار فاتورة وضمان موحدين ومشاركة بطاقة الضمان ورمز تحقق لا يتضمن رقم جوال العميل.
- سجل طلبات صيانة مرتبط بكل ضمان.

### العملات والضريبة

- العملات المدعومة: `SAR` و`AED` و`KWD` و`QAR` و`BHD` و`OMR` و`USD` و`SYP`.
- اختيار العملة الافتراضية حسب الدولة مع إمكانية تغييرها من إعدادات المتجر.
- دقة صحيحة للعملات ذات ثلاثة منازل، والليرة السورية بلا منازل عشرية.
- نسبة ضريبة قابلة للتعديل، ورقم ضريبي وسجل تجاري وعنوان متجر وبادئة فواتير.

### الإدارة والتقارير

- كتالوج منتجات يتضمن الباركود ورمز المخزون والتصنيف والسعر ومدة الضمان، مع التعديل والأرشفة.
- دليل عملاء موحد قابل للبحث والتعديل مع ربط العميل بكل ضماناته.
- فروع ونقاط بيع، وفرع رئيسي افتراضي لكل عملية.
- تقرير إجمالي المبيعات ومبيعات الشهر والضريبة ومتوسط الفاتورة وطرق الدفع.
- تصدير سجل المبيعات بصيغة `CSV` ومشاركته من الجهاز.
- سجل تدقيق لتغييرات المنتجات والضمانات والفروع والإعدادات.

## الحماية والبيانات

- طبقة `DamanakRepository` تفصل الواجهة عن العرض المحلي و`Supabase`.
- سياسات `RLS` تعزل بيانات كل متجر وتتحقق من عضوية المستخدم ودوره على الخادم.
- القيود المالية وحدود الخطة وتوليد أرقام الفواتير تُنفذ في قاعدة البيانات، لا في الواجهة فقط.
- لا يوجد مفتاح خدمة سري داخل تطبيق الجوال.
- يجب إنشاء مشروع `Supabase` مستقل لضمانك؛ لا تطبّق migrations على قاعدة تطبيق آخر.

مخططا قاعدة البيانات بالترتيب:

1. `supabase/migrations/20260824090000_damanak_core.sql`
2. `supabase/migrations/20260824130000_damanak_business_operations.sql`

## التصميم

- واجهة عربية من اليمين إلى اليسار بلون علامة واحد ودرجات حيادية.
- المظهر الفاتح والداكن يتبعان إعداد الجهاز تلقائياً.
- الحالات تعرض نصاً وأيقونة ولا تعتمد على اللون وحده.
- أهداف اللمس العامة لا تقل عن `48dp`، وتُحترم إعدادات تقليل الحركة.
- تقرير المراجعة وفق مهارة `Apple Design`: `../docs/DESIGN_AUDIT.md`.

## تشغيل العرض التشغيلي بلا تكلفة

عند التشغيل بلا مفاتيح يظهر عرض محلي واضح يحتوي بيانات متجر تجريبية، ولا يرسل البيانات إلى خادم:

```bash
flutter pub get
flutter run
```

## تفعيل المزامنة السحابية

1. أنشئ مشروع `Supabase` جديداً ومستقلاً.
2. اربط مجلد ضمانك بالمشروع الجديد فقط.
3. طبّق المخططين بالترتيب:

```bash
supabase link --project-ref YOUR_NEW_PROJECT_REF --workdir damanak_flutter
supabase db push --workdir damanak_flutter
```

4. انسخ `dart-defines.example.json` إلى `dart-defines.json` وأضف رابط المشروع والمفتاح القابل للنشر. الملف الحقيقي مستثنى من `Git`.
5. شغّل التطبيق:

```bash
flutter run --dart-define-from-file=dart-defines.json
```

flutter analyze

## خطة الوصول إلى الإنتاج

اكتملت داخل المستودع وظائف التطبيق، المخطط، الصلاحيات، التصميم، الاختبارات، وبناء Android والويب. المتبقي خارج الشيفرة ثلاثة عناصر فقط:

1. إنشاء مشروع `Supabase` مستقل وتطبيق المخططين وإدخال مفاتيحه العامة.
2. إنشاء مفاتيح توقيع المتاجر: Android release keystore وشهادات Apple وحسابات المتاجر.
3. تنفيذ قبول على أجهزة حقيقية: كاميرا وباركود، مظهر عربي، اتصال ضعيف، خلفية واستئناف، ثم عمليات الاشتراك الفعلية إن اختيرت بوابة دفع.

بوابة الدفع الإلكتروني اختيارية. النظام يعمل بلاها عبر رموز التفعيل وطلبات الاشتراك؛ إضافتها لاحقاً تحتاج حساب تاجر ومزوّد متوافقاً مع دولة الإطلاق.
