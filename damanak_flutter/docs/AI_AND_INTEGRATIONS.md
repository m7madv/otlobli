# الذكاء الاصطناعي والتكاملات في ضمانك

آخر تحديث: 30 أغسطس 2026

## سياسة المزود والتكلفة

- تحليل كتالوجات المنتجات غير الشخصية يبدأ بـ`Gemini 2.5 Flash-Lite`. يمكن تشغيله على الحصة المجانية بوضع `GEMINI_IMPORT_PRICING_TIER=free`، ثم يستخدم `OpenAI gpt-5.6-luna` مرة واحدة فقط إذا تعذر الاستخراج وكان المفتاح موجوداً.
- بيانات المطالبات لا تُرسل إلى حصة Gemini المجانية. مساعد المطالبة يستخدم `OpenAI` عند طلب المالك أو المدير فقط، مع `store: false`، ومن دون اسم العميل أو هاتفه.
- مرفقات المطالبة لا تُرسل إلا بعد اختيار صريح في نافذة التأكيد، بحد أول ملفين ومجموع `8 MB`.
- لا يحفظ أي تحليل منتج تلقائياً، ولا يقبل مساعد المطالبة أو يرفضها أو يغير حالتها. الموظف يراجع النتيجة ويؤكد تطبيق الفئة والأولوية فقط.
- الحدود الشهرية مفروضة خادمياً: بداية `10` ملفات منتجات و`5` مراجعات مطالبة، نمو `100/50`، توسع `500/250`. يوجد أيضاً حد أمان يومي يمنع إساءة الاستخدام.

الأسرار المطلوبة في مشروع Supabase الحقيقي:

```text
GEMINI_API_KEY=
GEMINI_IMPORT_PRICING_TIER=free
GEMINI_IMPORT_MODEL=gemini-2.5-flash-lite
OPENAI_API_KEY=
OPENAI_IMPORT_MODEL=gpt-5.6-luna
OPENAI_CLAIM_MODEL=gpt-5.6-luna
WEBHOOK_DISPATCH_SECRET=
```

يمكن حذف `OPENAI_API_KEY` إذا كان المطلوب تحليل كتالوجات Gemini فقط، لكن مساعد المطالبات والخيار الاحتياطي سيتوقفان برسالة إعداد واضحة. لا توضع هذه القيم في تطبيق Flutter أو Git.

## التكلفة المتوقعة

- عملية ناجحة داخل حصة Gemini المجانية: `0 USD` من رسوم النموذج.
- مثال كتالوج كبير يستخدم خيار OpenAI الاحتياطي، بافتراض `50,000` رمز إدخال و`2,000` إخراج: نحو `0.0124 USD`.
- مراجعة مطالبة نصية، بافتراض `2,000` إدخال و`400` إخراج: نحو `0.00088 USD`. خمسون مراجعة مشابهة تقارب `0.044 USD` شهرياً للمتجر.
- الصور وملفات PDF قد تزيد الرموز؛ لذلك تعرض الواجهة التكلفة التقديرية لكل عملية، والحصص تمنع فاتورة مفتوحة.

هذه أمثلة وليست سعراً ثابتاً؛ يحسب الخادم التكلفة من الاستهلاك الذي يعيده المزود.

## API وWebhooks

- التكاملات متاحة لمالك متجر باقة توسع فقط، ويطبق الخادم الاستحقاق حتى لو عُدلت الواجهة.
- مفتاح API يظهر مرة واحدة، وتخزن قاعدة البيانات بصمة `SHA-256` فقط. يمكن اختيار صلاحيات قراءة الضمانات، قراءة المطالبات، وإنشاء مطالبة ثم إلغاء المفتاح فوراً.
- المسارات الحالية: `GET /v1/warranties` مع مرشح إلزامي، و`GET /v1/claims`، و`POST /v1/claims`. الحد `300` طلب لكل مفتاح في الساعة.
- رابط Webhook يجب أن يستخدم `HTTPS`. الأحداث الحالية `claim.created` و`claim.updated`، من دون وصف المشكلة أو بيانات العميل.
- يوقع المرسل `${timestamp}.${body}` بخوارزمية `HMAC-SHA256` ويرسل `x-damanak-timestamp` و`x-damanak-signature`. يعيد المحاولة حتى ثماني مرات ولا يتبع إعادة توجيه.
- شغّل `dispatch-webhooks` من مهمة مجدولة آمنة كل دقيقة، مع الترويسة `Authorization: Bearer WEBHOOK_DISPATCH_SECRET`.

## قبل النشر

1. اربط مجلد `damanak_flutter` بمشروع Supabase الحقيقي فقط.
2. نفّذ جميع ملفات `supabase/migrations` بترتيب الاسم.
3. اضبط الأسرار ثم انشر `import-products-ai` و`analyze-claim-ai` و`damanak-api` و`dispatch-webhooks` و`warranty-card`.
4. اختبر حساباً من كل باقة، تجاوز الحصة، إلغاء مفتاح API، توقيع Webhook، وفشل المزود الأساسي وانتقاله إلى الاحتياطي.
5. لا تستخدم بيانات عملاء حقيقية قبل مراجعة سياسة الخصوصية واتفاقيات المعالجة مع المزودين.
