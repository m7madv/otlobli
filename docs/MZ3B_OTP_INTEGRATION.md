# ربط رموز Otlobli بخدمة MZ3B

## النطاق والعقد

اختار المالك `https://mz3b.com` بعد حذف مرسل WhatsApp القديم عمدًا. لا تعِد
ربط الجلسة القديمة أو استعادتها. المفتاح المُقدّم يخص مشروع «اطلبلي»؛ أكد
فحص `GET /api/v1/account/summary` الجاهزية، ولم يرسل رسالة أو يخصم رصيدًا.
المفتاح خادمي فقط ولا يُحفظ في المستودع أو `VITE_*` أو تطبيق الهاتف.

يبقى العنوان المشحون `https://84-8-100-128.sslip.io` كما هو:

- `POST /api/auth/whatsapp/start` يستقبل `{phone}` ويعيد `mode=external`
  و`otpExpiresInSeconds`؛ زر WhatsApp الحالي هو فعل طلب الرمز الصريح.
- `POST /api/auth/whatsapp/verify` يستقبل `{phone,code}` ويعيد جلسة العميل
  المعتادة؛ لا يصدرها إلا بعد `approved` لهوية المحاولة نفسها.
- لا تغيير لقاعدة Supabase أو RPC `create_customer_session` أو مخطط الجلسات.
  المزوّد يؤكد الرمز فقط، ولا يحصل على مفتاح Supabase أو رموز جلسات العملاء.
- يبقى iOS `86.244 (1112)` وAndroid `86.244 (1113)` دون تغيير ملفات العميل
  أو المزامنة أو البناء أو رفع أصول جديدة.

## الضبط والتخزين

في ملف الخادم الخاص `.env` فقط: `WHATSAPP_OTP_PROVIDER=mz3b` و
`MZ3B_API_KEY`، مع الحفاظ على `OTP_HASH_SECRET` وبيانات Supabase القائمة.
يحفظ الملف وصوره الاحتياطية بصلاحيات `600` داخل مجلد خاص بالمستخدم.
`MZ3B_OTP_DB_PATH` اختياري؛ الافتراضي `server/mz3b-otp-db.json`، وهو مستبعد
من Git مع ملف الكتابة المؤقت. لا يطبع الكود مفاتيح أو رموزًا أو استجابات
المزوّد الخام. أضيف نمط المفاتيح إلى حارس الأسرار.

هذا المحوّل خاص بتشغيل **عملية Node واحدة** على قرص دائم؛ تم التحقق من
`otlobli-wa` بنمط `fork_mode`. لا تستعمل عدة عمال/حاويات قبل تحويل التخزين
والحجز إلى قاعدة معاملات مشتركة. الحجز لكل هاتف متزامن، والكتابة الذرية
تسبق الإرسال. يخزن معرّف الهاتف كبصمة HMAC، ولا يخزن الرقم الخام أو الرمز
أو الجلسة أو مفتاح الخدمة. تلف الملف يوقف المصادقة بدل تصفير الحماية.

يُحفظ معرّف منع التكرار ووقت الموافقة وسياق معاملة الدخول قبل طلب المزوّد.
عند ضياع الاستجابة تُعاد العملية والجسم نفسيهما، بما في ذلك إعادة المحاولة
التلقائية الموجودة في العميل؛ لا إرسال بديل تلقائي ولا تغيير مرسل. عمليات
إعادة الإرسال المقبولة تحتفظ بميزانية التحقق السابقة. الحد المحلي خمسة
إرسالات/ساعة وخمس محاولات/15 دقيقة، مع حاجز IP القائم وحدود المزوّد.

بعد نجاح الرمز يُحجز للاستخدام مرة واحدة قبل RPC جلسة العميل. إذا فشل RPC
يمكن إعادة المحاولة بالرمز الموافق نفسه فقط؛ تحفظ بصمته لا نصه. ضياع رد
التحقق نفسه لا يُفسر نجاحًا، وقد يتطلب طلب رمز جديد بعد المهلة. لا تدّعي
ضمان استرجاع جلسة إذا انهارت العملية بعد حجز الرمز أو فقد رد إنشاء الجلسة.

`/health` يفحص جاهزية المزوّد وصلاحياته وقراءة مخزن المحاولات كل 30 ثانية
عند الطلب؛ لا يرسل رسالة أو يعيد وصل رقم. يحتفظ بعقد جاهزية Supabase.
في وضع MZ3B لا تُحمّل جلسات Baileys القديمة ولا يُستعاد أرشيفها؛ لا يحذفها
التغيير ولا يغيّر أرقام MZ3B أو أي مشروع آخر.

## حدود هذه الدفعة

الربط هنا **لرموز تسجيل الدخول وتوثيق الهاتف فقط**. تنبيهات WhatsApp القديمة
ليست مربوطة بواجهة موظفي MZ3B؛ ربطها يحتاج تحديد المستلمين وموافقتهم ونطاق
إشعارات صريحًا. تيليغرام والدفع والمحفظة ومنطق الطلبات لم تتغير.

التوثيق الرسمي: [واجهة الخدمة](https://mz3b.com/docs)،
[دليل التكامل](https://mz3b.com/integration.md)،
[عقد OpenAPI](https://mz3b.com/openapi.json). نتائج الفحص الحي لحظية وليست
دليل وصول. القبول النهائي يتطلب أن يطلب المالك رمزًا من التطبيق الحالي،
ويصل الرمز الفعلي ثم ينجح الدخول. لا تخمّن رمزًا ولا ترسل إلى رقم غير مصرح.

## الاختبارات والتراجع

`npm run test:server-otp-security` يشمل `test-mz3b-otp.mjs` بمزوّد وهمي:
إعادة التشغيل ومنع التكرار، حدود الإرسال والتخمين التراكمية، فشل/انتهاء
الرمز، اختلاف معرّف المحاولة، منع إعادة الاستخدام، فشل RPC والتزامن.
تشغّل أيضًا حواجز المصادقة وإدارة WhatsApp والأسرار وخدمات الإصدار وSHEIN.

قبل النشر تقارن بصمات ملفات الخادم الحي مع المصدر السابق، وتؤخذ نسخة خاصة
من الملفات المعدلة و`.env`. لا ترفع اعتماديات أو قاعدة جلسات أو ملفات
تطبيق الهاتف. أعد تشغيل عملية `otlobli-wa` وحدها بعد التحقق من الصياغة.
التراجع يعيد الملفات و`.env` من النسخة الدقيقة ويعيد تشغيل العملية نفسها؛
هذا يرجع إلى الحالة السابقة غير القادرة على الإرسال، وليس إلى رقم قديم صالح.
